# Automatic resume for D1

Use `colabs/clip_source_resume_drive_one_cell.py` in an A100 high-RAM Colab runtime. This is a separate execution version; the issued D1 scientific protocol, population, numerical operations, analysis, and original cell remain unchanged. The user's request for automatic resume supersedes only the original execution rule against saving checkpoints and automatically resuming.

After a disconnect, reconnect to a compatible GPU runtime and rerun **the same cell**. It automatically finds the unique compatible run on Drive, validates it, restores state, and continues. It does not itself provision or reconnect a Colab runtime. A completed run is recognized rather than repeated. If multiple independent compatible runs exist, set `RESUME_RUN` to the desired folder name; it never selects based on outcomes.

Native preparation is checkpointed every 25 updates and at the two native starting states. Branch training is checkpointed every 10 updates and at branch completion. Up to 25 native updates or 10 branch updates may be replayed if a disconnect interrupts checkpoint publication; recovery always uses the last successfully committed checkpoint. The same deterministic batches and RNG restore the same trajectory. Completed branches and complete calibrations are reused. An interruption during calibration repeats that state-preserving calibration if it was not yet sealed.

Checkpoints preserve mutable model tensors, buffers, parameter gradients, AdamW moments and counters, scheduler, RNG, module modes, backend flags, update offset, accumulated observations, and completed-branch metadata. The immutable pretrained tensors are reloaded and fingerprint-verified, reducing checkpoint storage. Native dataloader order is reconstructed without model updates, checked against saved batch identities and the loader's private generator state, then the saved training RNG is restored. Continuations use the frozen processed batch plans.

Each checkpoint is uploaded to a new file and verified by SHA256 before atomically publishing its pointer. The previous committed generation remains available; old generations beyond two are pruned only after publication. An interrupted upload leaves the prior pointer valid. A corrupt committed checkpoint, changed source bundle/population/environment, native replay mismatch, or scientific failure stops recovery instead of silently changing the experiment. A lease prevents overlapping writers; a disconnected runtime's lease expires after three minutes. Keep only one active notebook for the run.

New execution folders are `MyDrive/OTCO/evaluation_transfer/clip_source_resume_<timestamp>`. Result files retain the existing Drive inventory; checkpoints have their own authenticated pointers under `resume_state`. Preserve the entire folder for recovery. Plan for several GiB of additional Drive storage and at least 20 GiB free runtime disk. The cell prints `D1_CHECKPOINT_VERIFIED`, `D1_RESUME_TRUNK`, and `D1_RESUME_BRANCH` progress. Wait for `DRIVE_SYNC_COMPLETE` for final success.

For an interrupted run made with the original D1 cell, the new cell preserves the original folder and creates a new recovery lineage. It authenticates the original source manifest and result inventory, retains completed branches and calibration, and regenerates native starting states if needed. An unfinished old branch has no saved optimizer/model state and therefore replays from its start. Subsequent interruptions use the new checkpoints. Scientific/integrity failures are not treated as ordinary disconnects.

Logical experiment totals remain 6,900 updates. Attempt-level execution events record newly executed native and branch updates separately when the attempt can flush; a hard runtime kill can leave uncommitted work uncounted, so these are not guaranteed cumulative GPU-step totals; repeated work after disconnects is not independent evidence. Checkpoint I/O and recovery decisions never use reporting utility to choose a treatment.
