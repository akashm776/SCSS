# D2-P v1: controlled pairwise-margin preflight

D2-P is implemented as an observational acceptance audit. It never launches D2,
regenerates native trunks, evaluates reporting utility, or calls an optimizer step.
A PASS applies only to the authenticated initial states and exposures on the pinned
numerical stack. It does not certify future feasibility or explain D1's results.

## Run

Paste the **entire** `colabs/clip_placement_preflight_drive_one_cell.py` into one
high-RAM **A100 40 GB** Colab cell. Its editable `D1_RUN` points to the completed
`clip_source_resume_20261015T014921_451960Z` folder. Keep that entire input folder.
The runner reads its checkpoints without altering it. D0 files are not required
in Colab: the authenticated gap-input manifest is embedded in the source bundle.

The numerical contract retains D1's torch 2.11.0+cu128, torchvision 0.26.0+cu128,
Python 3.13.15, CUDA 12.8 and other pinned packages. The bootstrap installs the
issued non-Torch dependencies before importing the worker; it does not replace
Torch or bypass runtime identity checks. Select the matching runtime first.

Output goes to a separate `clip_placement_preflight_v1_<bundle-hash>` Drive folder.
It contains small JSON evidence, not model checkpoints. Read `acceptance.json`:

| Status | Meaning |
|---|---|
| PASS | All 624 exposure-batch/state audits and six calibration cells passed. |
| FAIL | A specific execution-contract violation was demonstrated. |
| INCOMPLETE | Required evidence is missing after an operational/numerical interruption. |
| INVALID | Provenance or configuration does not identify the prescribed experiment. |

**The audit stops at its first demonstrated contract violation.** This is a
cost-saving acceptance policy, not filtering: coverage and remaining checks stay
explicitly incomplete, the violation stays visible, and D2 cannot launch. A
subsequent invocation reuses the failure record instead of retrying it away.
A complete PASS requires all **630** check records.

On an operational interruption, rerun the same cell. Every invocation has a new
attempt record, references previous attempt hashes (including interrupted RUNNING
attempts), and lists reused checks. A completed check is reused only with the same
run configuration and a verified record hash. An interrupted check is rerun from
its authenticated starting checkpoint and common RNG. A changed code, gap,
configuration or environment cannot silently merge with old evidence. A repaired
single-writer lease protects only the new output directory.

Even PASS prints `D2_TRAINING_NOT_LAUNCHED`. Launching D2 is a separate task.

## Frozen inputs and provenance

The dependency sequence is:

1. `configs/clip_placement_preflight.json`: treatment, numerical and calibration rules.
2. `scripts/build_clip_placement_gap.py`: authenticated D0 starting geometry →
   `configs/clip_placement_gap.json`.
3. Run configuration: design, gap-manifest hash, derived gap, exact input reference,
   source hashes, repository commit and numerical environment.
4. Check records and acceptance record referencing that run configuration.

`configs/clip_placement_inputs.json` pins the completed D1 preparation metadata and
three latest trunk pointers/blobs. Expanded checkpoint100/500 states additionally
must match D0's frozen full snapshot and weight fingerprints. All processed batch
and caption identities must equal the archived D1 identities. H source IDs remain
state-specific, exactly as in D1. No model weights or outcome values are inferred
from a filename alone.

The source bundle includes the pinned repository base plus checksummed overlays,
including the existing scoring, carrier, loss, checkpoint, calibration and data
helpers. `placement_source_manifest.json` is generated by the bundle builder.
The issued D0/D1 code and historical Colab bundles remain unchanged.

The dedicated gap manifest was built from authenticated D0 records at native
starting checkpoints only. For each D1-masked continuation exposure at each state:

`half_bracket = (nearest_positive_C_margin - nearest_nonpositive_I_margin) / 2`.

C uses the smallest strictly positive margin; I uses the smallest absolute
nonpositive margin; ties use ascending batch index. Repeated exposures retain
multiplicity. Calibration is excluded. Take a median per seed across both states
and streams, then the median of the three seed medians. An even-count median is
the arithmetic mean of its two central values.

| Seed | Included state/exposure records | Median half-bracket |
|---|---:|---:|
| 271828 | 7,084 | 0.0011215880513191223 |
| 161803 | 7,184 | 0.0010687001049518585 |
| 141421 | 7,066 | 0.001064389944076538 |

**Frozen global cosine gap: 0.0010687001049518585.** Total: 21,334 records.
Each record carries checkpoint-linked context, source/query identities, shard hash,
C/I IDs and margins. The builder refuses to overwrite a different manifest.
This deterministic rule is not a claim that the resulting gap is informative or
resolvable in bf16. The acceptance audit decides whether v1 can be executed.

To reproduce the gap locally (the original D0 shard folder is required):

```sh
.venv/bin/python -m scripts.build_clip_placement_gap /path/to/completed/D0
```

## Three numerical paths

The carrier is the **existing D1 `candidate(..., 'H_Synth')` path**, including its
dense 0.5 weight matrix, autocast matmul and normalization. The original live `z0`
provides the surrogate backward path.

Detached copies of the actual live query, positive and carrier are explicitly
normalized in FP32 with autocast/TF32 disabled. Define `p_geom`, project the carrier
onto the orthogonal query component, and construct the requested cosine target
for `r = -delta, 0, +delta`. Normalize only that detached FP32 target. Then:

```python
target = target_fp32.to(z0.dtype)
z = target.detach() + (z0 - z0.detach())
```

There is no differentiable normalization after this expression. It is a deliberate
surrogate derivative, not the derivative of rebuilding the constrained generator.

Actual numerical evidence is captured separately:

- `p_sim`: native raw-similarity diagonal;
- `ell_plus`: native scaled-logit diagonal;
- `s_aux`, `e_aux`: actual auxiliary similarity and scaled logit;
- `r_train = p_sim - s_aux`, `g_logit = ell_plus - e_aux`;
- `A`: the D1 auxiliary native-row partition using detached auxiliary scale;
- `m_loss`: actual pre-softplus input;
- `P_plus`, `sigmoid_m`, scale and scale/wiring residuals.

Native CLIP retains its own live scale. Auxiliary scale is detached and its native
partition remains differentiable, matching D1. The captured auxiliary loss is
also compared with the existing D1 loss helper. This wiring check is not an
independent proof of numerical truth.

### v1 thresholds

| Requirement | Frozen threshold |
|---|---:|
| Global gap | >= 1e-5 |
| Original D1 mixture norm | > 1e-6, finite |
| Orthogonal norm | > 1e-4 |
| Target cosine | absolute value <= 1 - 1e-5 |
| FP32 target unit-norm error | <= 1e-6 |
| FP32 target-margin error | <= max(1e-7, 0.01 delta) |
| Actual training similarity-margin error | <= 0.1 delta |
| Actual logit-gap error, including Boundary | <= 0.1 tau delta |
| Wrong/Correct actual logit sign | strictly negative/positive |
| Adjacent actual similarity-margin separation | >= 0.8 delta |
| Candidate-logit gradient relative vector error | <= 1e-5 |
| Candidate-logit gradient cosine | >= 0.99999 |

Initial acceptance requires all three targets on the exact unchanged D1 mask at
both starting states, including calibration. Tests compare the candidate-logit
VJP through the **live source feature → D1 carrier → ST → logit** path with H-Uniform
at identical feature tensors. Both FP32 and actual autocast probe paths are tested.
Full auxiliary source/query gradient norms and cosines are descriptive and are
expected to differ. These checks do not claim full encoder parameter gradients
are equal. Full model parameter gradients are used for calibration.

Counterfactual diagnostics operate on detached/clone feature tensors. Candidate,
logit and loss values before/after diagnostics must be identical, as must model,
optimizer, scheduler, RNG, gradients, buffers, modes and backend state. Every
observational call restores those values on success and exception. No GradScaler
is instantiated for the existing bf16 path; autocast contexts restore on exit.

The future D2 runtime rule remains assigned-target validity only. The core target
function accepts an assigned arm without constructing infeasible unused arms.
This package contains no D2 continuation loop. Initial PASS is not a promise that
the assigned target remains valid after training updates.

## Calibration

Calibrate only the three new placement arms, using the four frozen scheduled
batches per seed/state and common checkpoint100 RNG for each observational call.
Native loss includes all 64 pairs. Auxiliary loss averages over eligible queries.
An empty mask produces differentiable zero; its cosine is undefined.

`c = mean_four_batches(||g_aux|| / ||g_native||)` and `alpha = 0.02 / c`.

Every native norm and every nonempty auxiliary norm must be finite and >1e-12;
empty auxiliary gradients must be zero. Require finite `c > 1e-12` and positive
finite alpha. **There is no coefficient cap in v1.** Recompute weighted model
parameter gradients and require the scheduled mean ratio within 5% relative error
of 0.02. Native gradients must replay exactly. Report the treated-batch conditional
ratio separately. Coefficients are shared across streams within seed/state/arm.
The configuration explicitly versions D1's empty-calibration validity rule; the
actual frozen D1 population currently has no empty eligible batches.

No H-Uniform coefficient is silently recalibrated. D2-P authenticates D1
preparation inputs but does not certify reused Native/H-Uniform endpoint outcomes.
Any eventual D2 reuse must authenticate those branch outcomes separately. The
planned primary placement contrast does not depend on either historical control.

## Evidence and failure interpretation

A violation records context, numerical path, requirement, observed value,
threshold and affected local row indices where available. Map local indices
through the recorded `eligible_queries`. Raw actual placement values are retained
on precision failures. Mathematical infeasibility, numerical headroom, orthogonal
conditioning and precision-contract errors have separate requirement codes.
Unexpected NaNs, kernel errors and other undiagnosed exceptions are operational/
numerical interruptions, not evidence of a geometric scientific failure.

Headline status and provenance validity, execution completeness, coverage,
violations, operational error and launch eligibility are separate fields. FAIL
can coexist with unperformed checks. A missing primary branch in future D2 cannot
be converted into a survivor-only aggregate.
